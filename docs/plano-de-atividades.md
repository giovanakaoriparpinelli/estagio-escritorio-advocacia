# Plano inicial de atividades

## Objetivo geral

Proporcionar experiência prática em engenharia de software por meio da análise, construção, validação e documentação de uma solução de software real.

## Atividades previstas

| Fase | Atividades | Evidências |
|---|---|---|
| Descoberta | entender o problema, usuários e restrições | ata, mapa de contexto, requisitos |
| Planejamento | decompor o trabalho e priorizar entregas | backlog, cronograma, decisões técnicas |
| Projeto | modelar solução, dados, interfaces e integrações | diagramas, ADRs, protótipos |
| Implementação | desenvolver funcionalidades com revisão de código | commits, pull requests, código |
| Qualidade | criar testes, revisar segurança e tratar falhas | testes, relatórios, correções |
| Entrega | documentar, publicar e acompanhar a solução | manual, pipeline, logs e métricas |
| Reflexão | consolidar aprendizados e resultados | relatório parcial/final, autoavaliação |

## Critérios de acompanhamento

- qualidade e clareza das entregas;
- cumprimento do plano e comunicação de impedimentos;
- uso de controle de versão e revisão de código;
- cobertura de testes proporcional ao risco;
- documentação das decisões e resultados;
- compatibilidade das tarefas com o curso.

O plano deve ser ajustado e aprovado pelas pessoas responsáveis antes de ser usado como documento oficial.
